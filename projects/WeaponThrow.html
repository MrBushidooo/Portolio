Project Overview

A third-person weapon throw and recall system built in Unreal Engine 5 using C++ and Blueprints, focused on creating responsive and satisfying action combat interactions inspired by modern melee combat games. The project features throwable weapon mechanics with collision-based damage, spline-based return movement, hover behaviour, and dynamic recall back to the player's hand.

The system was designed as a reusable gameplay framework capable of handling weapon travel, impact detection, gameplay state transitions, and smooth visual feedback while maintaining strong gameplay feel and combat responsiveness. Custom movement logic and spline interpolation were implemented to create fluid return trajectories that dynamically adapt to player movement during recall.

Core Features & Systems

Gameplay Architecture

The throwable weapon system is built around a modular state-driven architecture that separates character input, animation timing, movement behaviour, and weapon logic into independent gameplay layers.

The player character handles:

  • Input processing
  • Camera and movement control
  • Weapon ownership
  • Attack state management

The weapon actor independently handles:

  • Projectile simulation
  • Flight behaviour
  • Collision state switching
  • Rotational/spin behaviour
  • Recall logic
  • Spline-based return movement

The system operates through a finite state flow:

InHand → Flying → Returning → InHand

Each state governs the weapon's movement, collision behaviour, attachment state, and recall logic, ensuring deterministic gameplay flow while preventing overlapping actions such as repeated throws or recalls.

Weapon execution is synchronized through custom AnimNotify events, allowing the throw to occur precisely at the correct animation frame rather than directly on input press, resulting in tighter combat responsiveness and animation integration.

Throw System

The throw system synchronizes gameplay execution with animation timing rather than triggering directly on input. When the player attacks, the character enters an attacking state while the actual release is handled through a custom AnimNotify inside the throw animation.

At the notify frame:

  • The weapon detaches from the hand socket
  • The player's control rotation is converted into a throw direction
  • The weapon transitions into the Flying state
  • Projectile simulation is activated using UProjectileMovementComponent

Using controller rotation instead of character forward direction ensures camera-accurate throws during traversal and directional changes.

Flight Behaviour

Once thrown, the weapon enters a projectile-driven flight state configured for gravity-free directional travel with sweep collision enabled.

During flight, the system:

  • Tracks distance from the initial throw position
  • Applies rotational spin behaviour
  • Monitors conditions for automatic recall

A configurable maximum throw distance prevents indefinite projectile travel and triggers recall once exceeded. Separating flight into its own state allows the weapon to simulate independently from the player while maintaining predictable behaviour.

Dynamic Recall System

The recall system transitions the weapon from projectile simulation into spline-driven interpolation to create a curved return path. When recall begins, projectile movement is disabled and a runtime spline is generated between the weapon and the player's hand socket.

The spline uses:

  • A start point at the weapon location
  • An offset midpoint for curvature
  • A live endpoint attached to the player's hand socket

The endpoint updates continuously during recall, allowing the weapon to follow the player in real time while moving or changing direction. Movement is interpolated along the spline using normalized alpha progression before the weapon reattaches to the character socket on catch completion.
